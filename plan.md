Hackathon Plan: The Agent That Calls You When Calls Fail

Track: Workplace Assistance (ps31)
Entry: solo · Time: 2 days · Tools: Claude Code + Cursor
Stack: Agora Conversational AI (required) · Murf Falcon TTS (required) · Groq gpt-oss-120b · Plivo (calling) · Telegram Bot API · Notion or Slack (tickets) · RAG knowledge base

1. The idea in one paragraph

A big customer's calls start failing. Before the engineer even knows, the agent has started investigating and calls them. When they pick up, it explains what's happening, answers follow-ups fast from a live case file and an internal knowledge base, and gives a confidence score. If it isn't sure, it says so honestly and calls back once it is. Then, after voice confirmation, it raises a ticket and drafts the customer email. If the engineer misses the call, it pings them on Telegram. A timer shows alert-to-diagnosis time against a manual baseline.

2. How it meets the track requirements
Required step	How the project covers it
Initiate: natural voice via Agora + Murf	The agent rings the engineer; the whole conversation runs on Agora Conversational AI with a Murf Falcon voice (verified in spike S1)
Understand: retrieve enterprise info, identify action	Reads the live case file (call records, hypotheses) + RAG over docs, runbooks and the customer profile
Execute: tool calls that perform meaningful actions	Raises a real ticket (Notion or Slack) and drafts the customer email
Confirm: outcome, error handling, confirmation for critical actions	Asks "want me to raise a ticket and draft the email?" before acting; one action fails on purpose and is retried; says "I'm not sure" honestly when below threshold
Follow up: update systems, summary, follow-ups	Callback when confident; incident summary written to the ticket; Telegram summary on a missed call
Measurable efficiency (encouraged)	Dashboard timer: alert → acknowledged → diagnosed → ticket raised, compared with a manual baseline you timed yourself on the same scenario
Tech focus: RAG, tool calling, MCP, enterprise APIs	RAG knowledge base; tool calls; ticketing through an MCP server if time allows (direct API is fine otherwise)
3. Minimum demo scope (what gets built)
One failure scenario. Carrier rejection is the true cause.
Three hypotheses: carrier rejection (true), number formatting (ruled out), auth/config (ruled out).
Scripted evidence timeline. Evidence arrives in stages so confidence climbs honestly and identically every run.
Confidence = simple formula, computed in code: share of failures matching the hypothesis + bonus if steady over time. Never generated by the LLM.
Knowledge base: reuse your Pipecat RAG setup. A few hangup-cause/carrier docs, two short runbooks, one customer profile (plan, routes, one past incident).
One real connected system: Notion database or Slack channel for tickets (pick one). The email is drafted and shown on screen, not sent.
One callback after about 60 seconds, or as soon as confidence crosses the threshold.
Telegram: one message with a "Call me now" button.
Dashboard: one page showing the confidence meter, hypotheses, ruled-out list, stage timer, and the manual vs. agent comparison.

Cut entirely (pitch them as next steps): Jev, remediation/failover, real test calls, escalation chains, on-call rotation, anomaly detection, Telegram voice notes.

4. Architecture

                 +-------------------------------------+----------------------------+
                 v                                     v                            v
          [Investigator]                        [Caller: Plivo]              [Telegram bot]
    3 fixed checks -> case file          ring -> SIP -> Agora agent        missed-call fallback
                 |                                     |
                 v                                     v
         [Case file store] <-- reads every turn -- [LLM proxy] --> Groq gpt-oss-120b
                                                       |   (case file + RAG injected each turn)
                                                       v
                                           [Tools: ticket (Notion/Slack), email draft]

[Dashboard] meter · hypotheses · ruled out · stage timer · manual vs agent

Key rules

The investigator is plain code running fixed checks, never an open-ended LLM agent. The LLM only narrates the case file.
The LLM proxy sits between Agora and Groq and injects the latest case file + relevant RAG snippets on every turn. That's what keeps answers fast.
The opening line uses only alert-time facts (customer, failure rate, since when), so it never waits on the investigator.
Actions (ticket, email) run after voice confirmation, in the background, so the conversation never stalls.

State machine: ALERTED → CALLING → (ANSWERED | MISSED → RETRY → TELEGRAM) → IN_CALL → (CONFIDENT → CONFIRM_ACTIONS → EXECUTE | UNSURE → WAITING → CALLBACK) → RESOLVED

5. Risks, ranked
Risk	Why it matters	Mitigation
Phone path into Agora (Plivo → SIP → Agora Agent Studio) is unproven with Plivo	It's the wow moment and the riskiest build	Timebox to 3–4 hours. Fallback: agent rings in the browser (Agora "in apps" path); everything else stays the same
Custom LLM endpoint may not be available for phone agents in Agent Studio	The whole speed design depends on the proxy	Spike S2. If it fails, use the browser path for the voice leg
Murf Falcon may not be the voice on the phone path	Hard requirement of the track	Verify in S1. If the phone path can't use Murf, use the browser path
Turn latency across speech-to-text → proxy → LLM → TTS	Target: fast path ~2–3 seconds, slow path under 10	Measure each hop in S4; short prompt; low reasoning effort; llama-3.3-70b-versatile as a one-line fallback
Filler-then-answer streaming may get cut off	Needed for the "give me five seconds" moments	Spike S3. Fallback: spoken wait message, answer on the next turn
Voicemail "answers" the call	The agent talks to voicemail instead of falling back to Telegram	Turn voicemail off on the demo phone; treat "answered but silent for N seconds" as missed
SIP gotchas	Agora's docs warn that a transport mismatch fails silently, and ~30-second drops point to a SIP session timer	Check both first when debugging the phone path
Groq free tier (~8K tokens/min on this model)	Rehearsals will hit 429 errors	Upgrade to the Developer plan before full run-throughs (card enabled for international payments)
Rules / accounts	Extra providers and work access	Confirm Plivo, Groq and Telegram are allowed; use a personal Plivo account or clear work access with your manager; never use real customer data

Budget: Groq gpt-oss-120b at $0.15 / $0.60 per million input/output tokens comes to about ₹500–1,000 for the whole build including rehearsals. Plus a small Plivo balance.

8. Demo script (~3 minutes)
Setup (15 seconds): "When a big customer's calls fail, an engineer loses the first chunk of time just figuring out what's wrong. This agent does that before you even pick up."
Trigger the failure. The dashboard shows the alert, and your phone rings on stage.
(Optional) Decline → Telegram buzzes on the projector → tap "Call me now."
Pick up → alert-time summary → two fast follow-ups → one "give me five seconds" question → an answer citing the runbook.
"So what's the issue?" → 55%: "Not sure yet. I've ruled out number formatting and auth. I'll call you back."
Hang up; talk to the judges while the meter climbs.
Phone rings again → "Found it. Carrier X has been rejecting calls since 10:42, 92% confident. The runbook says fail over and notify the customer. Want me to raise a ticket and draft the email?" → "Yes" → the ticket call fails once, the agent retries → ticket and email appear on screen.
Close (20 seconds): the comparison slide, manual time vs. agent time on the same scenario, then map what they saw to Initiate → Understand → Execute → Confirm → Follow up.

Tier C in detail: what the worst case still includes
The "call": the dashboard shows an incoming-call screen with a ringtone; you click answer and join the Agora conversation (in-app path). If even auto-ringing breaks, a "Join incident call" button.
Voice: Agora Conversational AI with a Murf Falcon voice. Non-negotiable, since it's the track's hard requirement.
Investigation: no live checks. A scripted case file: a JSON that a simple timer updates in stages (55% → 92%). Same story on screen, almost no code.
Knowledge: if RAG isn't wired up, paste the two runbooks and customer profile directly into the system prompt. They're small enough to fit.
LLM: if the custom proxy fails, use Agora's native Groq config and put the scenario in the system prompt. Answers will be less "live" but the conversation still works.
Action: after voice confirmation, one Slack incoming-webhook POST that creates the "ticket" message, with the drafted customer email inside it. One HTTP call, nearly impossible to break.
Error handling: say "I'm not sure yet" at 55% (already in the script). The deliberate tool failure is optional at this tier.
Follow-up: the agent rings again in the browser at 92%. If the callback breaks, the incident summary posted to Slack is the follow-up.
Efficiency: stage timer on the dashboard + the manual-baseline slide. The slide needs no code at all.
Dropped: Telegram, real phone calls, live investigator, MCP.
